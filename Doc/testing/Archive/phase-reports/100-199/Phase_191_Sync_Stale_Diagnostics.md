# Phase 191 - Sync-Stale Diagnostics

Date: 2026-04-25

Document class:

- closed evidence

## Goal

Populate typed warning diagnostics for sync-engine stale states without changing rendered UI behavior or raw diagnostic strings.

This phase covers stale cached-state and automatic-sync-overdue warnings generated by the sync engine.

## Why This Phase Exists

`Phase 185` added the additive typed diagnostic model. `Phase 186` through `Phase 190` populated source-selection, fallback, credential, host-access, page-session, usage-threshold, and policy-only diagnostic metadata. This phase moves the local sync engine stale warning family into typed metadata while preserving the exact raw warning text.

## What Changed

- `src/providers/diagnostics.ts` now includes a reusable sync-stale diagnostic builder.
- `src/background/sync-engine.ts` now populates `warningDiagnostic` for cached-state stale warnings generated by the sync engine.
- `src/background/sync-engine.ts` now populates `warningDiagnostic` for automatic-sync-overdue stale error states generated by the sync engine.
- Existing provider-owned warning diagnostics are not overwritten when the sync engine only updates freshness labels.
- `src/providers/diagnostics.test.ts` verifies the sync-stale builder preserves raw warning messages.
- `src/background/sync-engine.test.ts` verifies cached-state stale, automatic-sync-overdue, and provider-warning preservation behavior.
- `phase191-sync-stale-diagnostics-review.mjs` verifies code markers, docs, tests, and closeout references.

## Runtime Behavior

Rendered UI behavior is unchanged in this slice.

Existing raw diagnostic strings remain the displayed source truth:

- `ProviderSnapshot.warningReason`
- `ProviderSnapshot.sourceSelectionReason`
- `ProviderSnapshot.sourceFallbackReason`

The new typed diagnostics are additive metadata for future localization and source-state classification work.
