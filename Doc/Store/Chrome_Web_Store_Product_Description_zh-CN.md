AI 使用仪表盘是一个小小的 AI 编码配额驾驶舱：配额、设置阻塞、同步健康状态，都放在一个地方。

打开 Chrome 工具栏弹窗，先快速瞄一眼；需要细节时，再进入侧边栏或完整页面仪表板。少翻几个页面，多写几行代码。(^_^)

它支持 Codex、Cursor、Claude Code、Gemini Code Assist 等编码工作流，并清楚标出每个来源是精确值、部分信息、使用窗口、策略说明，还是暂时不可用。

它不要求你粘贴 cookie，也不要求你粘贴原始浏览器 auth header。设置、可选 API 凭据、页面绑定、缓存快照、导入导出文件和 Chrome Sync 数据都保存在你的 Chrome 配置里。

它能帮你看到什么

• provider 健康状态和设置阻塞项
• provider 暴露时的剩余使用窗口和重置时间
• 来源类型：API、已登录页面、部分页面上下文、文档策略或不可用来源
• 快照新鲜度和同步状态
• 工具栏标记和工具栏图标行为
• 用于自有配额端点的自定义 HTTP/HTTPS JSON 来源
• 传统进度区间，或可编辑的剩余颜色渐变显示
• 语言、主题、popup 外观、进度样式、provider 顺序和导入导出设置

日常使用时，它想解决什么

AI 编码助手很好用，但配额页、账号状态和权限问题很容易让人一头雾水：刚才还能跑，下一秒可能就遇到额度窗口、权限缺失、登录会话过期，或者某个 provider 的配额策略变了。

AI 使用仪表盘想做的就是把这些状态收进一个安静的小面板里。你可以先快速瞄一眼，真的需要时再展开细节。一个小仪表盘，不是又一个要管理的项目。✨

Provider 覆盖会如实标注

不同 provider 暴露的信息不一样：

• 有些路径可以显示实时或接近实时的使用窗口
• 有些路径只能显示部分页面上下文
• 有些路径在当前版本只是策略说明
• 有些 provider 可能需要已登录页面、可选 host access 或 API 凭据
• 首次使用时，如果阻塞点是 host 权限，Provider 卡片会显示聚焦的“授予访问”动作
• 各家 dashboard、API、配额文案和策略都可能变化

当某个来源不可用或只能提供部分信息时，扩展会标出这个状态，而不是编造一个数字。

隐私和权限

AI 使用仪表盘采用保守设计：

• 不要求粘贴 cookie
• 不要求粘贴原始浏览器 auth header
• 可选主机权限只用于支持的 provider 来源
• 自定义 JSON 来源只会请求用户批准的 HTTP 或 HTTPS 端点，并省略浏览器凭据
• favicon 权限只用于可选的“工具栏图标匹配 provider”功能
• 从本地图片生成渐变时，图片只在浏览器内处理，原始图片字节不会上传或保存
• 只运行打包脚本，不加载远程代码
• 设置和缓存数据保存在 Chrome 配置里，除非你主动导出

这不是 OpenAI、Cursor、Anthropic、Google、JetBrains 或其他 provider 的官方产品。
